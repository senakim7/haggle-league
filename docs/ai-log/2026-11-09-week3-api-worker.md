- 맡긴 일: "로그인한 사용자가 에이전트를 만들고, 워커가 경기를 실행한다"

## AI가 만든 것

- `packages/db`: Drizzle 스키마(Better Auth 테이블, agents, agent_versions, scenarios, matches, turns)와 첫 마이그레이션. 각 쪽이 에이전트 버전과 하우스 봇 중 정확히 하나인지, `s < b`인지를 CHECK 제약으로 막는다. 테스트는 PGlite로 Docker 없이 돈다
- `apps/api`: Hono + Better Auth(카카오·GitHub, 개발용 이메일 로그인). 에이전트 생성(사용자당 3개), 전략이 바뀔 때만 새 버전, 연습 경기 요청(한국 시간 하루 3회), 경기 조회(끝나기 전에는 한도·속마음 없음)
- `apps/worker`: BullMQ 워커. 조건부 UPDATE로 경기를 가져가고, 엔진을 돌린 뒤 턴과 결과를 한 트랜잭션으로 저장한다. 하루 쿼터는 Redis에서 센다
- `docker-compose.yml`(로컬 Postgres·Redis), `.env.example` 항목, 루트 스크립트

## AI가 틀린 것과 잡아낸 방법

1. **CSRF 방어를 잘못 믿었다.** Hono의 `csrf()`를 넣으면 다른 출처의 쓰기 요청이 막힌다고 가정했는데, 이 미들웨어는 폼 형식(`text/plain`, `multipart` 등) 요청만 검사한다. 게다가 본문 파서가 content-type을 보지 않고 JSON을 읽어서, 다른 사이트의 폼이 `text/plain`으로 JSON을 보내는 우회가 가능했다. "다른 출처 쓰기 거부" 테스트가 201을 받으며 실패해서 드러났다. Origin을 직접 검사하고 `application/json` 본문만 받도록 바꿨다.

## 내가 확인해야 할 결정 (AI가 임시로 정함)

- **카카오 이메일 자리표시.** Better Auth는 email이 필수라 `kakao-<id>@users.haggle.invalid`를 넣는다. `.invalid`는 실제로 존재할 수 없는 도메인이다. 동의항목은 닉네임만 요청하고 프로필 사진은 저장하지 않는다.
- **카카오·GitHub ID는 `account` 테이블에.** 설계서의 `users.kakao_id`, `github_id` 대신 Better Auth 기본 구조를 따랐다. 설계서 데이터 모델 표를 고쳐야 한다.
- **개발용 이메일 로그인.** OAuth 앱 없이 개발·테스트하려고 `AUTH_DEV_LOGIN=1`일 때만 켠다. 운영에서 켜면 시작 단계에서 실패한다.
- **연습 경기 횟수는 한국 시간 자정에 초기화.** LLM 쿼터는 태평양 시간 자정 기준이라 둘이 다르다. 사용자에게는 한국 시간이 자연스러워서 이렇게 뒀다.
- **무효가 된 연습 경기도 하루 3회에 포함된다.** 실제 실행에서 키가 없어 무효가 된 경기도 횟수를 썼다. 우리 쪽 장애로 무효가 된 경기는 빼는 것이 맞아 보이지만, 아직 바꾸지 않았다.
- **도중에 죽은 경기는 무효.** 재시도로 이어 붙이지 않는다. 연습 경기에는 충분하지만, 리그(5주차)에서는 재경기를 다시 큐에 넣을지 정해야 한다.
- **`@hono/zod-openapi` 대신 zod 직접 검증.** 설계서는 zod OpenAPI지만 3주차에는 의존성을 줄였다. 웹(4주차)에서 Hono RPC 타입으로 충분한지 보고 정한다.
- **설계서의 `cost_usd` 대신 `llm_calls`, `tokens_in`, `tokens_out`.** 무료 티어 결정에 맞췄다.
- **라이브 관전은 아직.** 워커가 경기가 끝난 뒤 턴을 한꺼번에 저장한다. 4주차에 엔진에 턴 콜백을 넣고 Redis 발행·SSE를 붙인다.
